# ChipletTrust

Open-source RTL and verification framework for trusted bring-up, attestation,
session freshness, lifecycle control, and fault containment in multi-chiplet
systems.

> **Status:** M1 engineering baseline. The current measurement and attestation
> transforms are deterministic verification primitives, **not cryptography**
> and **not SPDM-compliant**. They exist so lifecycle, freshness, containment,
> assertions, and verification infrastructure can be exercised before a
> reviewed cryptographic backend is integrated.

## Implemented

- synthesizable lifecycle controller with irreversible security transitions
- PCR-like measurement bank with deterministic extend semantics
- challenge/response attestation engine
- bounded `(session_id, challenge)` replay guard
- session-bound secure-attestation wrapper
- per-chiplet trust/isolation manager
- sticky containment on failed attestation, tamper, or heartbeat timeout
- SystemVerilog assertions for lifecycle and containment invariants
- Python golden/reference model
- adversarial tests for replay, tamper, rollback, bad measurement, and
  heartbeat loss
- CI using `pytest` and Icarus Verilog

## Trust flow

```text
RESET -> lifecycle check -> measurement collection
      -> session/challenge freshness check
      -> transcript-bound attestation
      -> expected-response comparison
      -> TRUSTED or ISOLATED
```

Isolation is sticky until reset. A tamper event, heartbeat timeout, or failed
attestation causes containment.

## Quick start

```bash
python -m pytest -q
python scripts/run_smoke.py
make rtl
```

The RTL target runs the manager smoke test, standalone replay-guard test, and
the integrated secure-attestation-session regression.

## Security boundary

M1 deliberately separates **control-plane verification** from cryptography.
The current transforms are reversible/deterministic so expected responses can
be generated by the Python model. They must be replaced by reviewed
cryptographic constructions before any security-sensitive use.
