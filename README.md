# ChipletTrust

Open-source RTL and verification framework for trusted bring-up, attestation, lifecycle control, and fault containment in multi-chiplet systems.

> **Status:** M0 engineering baseline. The current attestation transform is a deterministic verification primitive, **not cryptography** and **not SPDM-compliant**. It exists so the lifecycle, measurement, manager, assertions, and test infrastructure can be exercised before a real cryptographic backend is integrated.

## M0 goals

- synthesizable lifecycle controller with irreversible security transitions
- PCR-like measurement bank with deterministic extend semantics
- challenge/response attestation engine
- per-chiplet trust/isolation manager
- SystemVerilog assertions for lifecycle and containment invariants
- Python golden/reference model
- adversarial tests for replay, tamper, rollback, bad measurement, and heartbeat loss
- CI using `pytest` and Icarus Verilog


## Trust flow

```text
RESET -> lifecycle check -> measurement collection -> challenge
      -> attestation response -> expected-response comparison
      -> TRUSTED or ISOLATED
```

Isolation is sticky until reset. A tamper event, heartbeat timeout, or failed attestation causes containment.

## Quick start

```bash
python -m pytest -q
python scripts/run_smoke.py
```

For RTL smoke compilation:

```bash
make rtl
```

## Security boundary

M0 deliberately separates **control-plane verification** from cryptography. `attestation_engine.sv` uses a reversible mixing transform so expected responses can be generated by the Python model. It must be replaced by a reviewed cryptographic construction before any security-sensitive use.
